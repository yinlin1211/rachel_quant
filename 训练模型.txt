训练模型计划
============

一、gaotj 那套模型是什么
------------------------

目的是训练颗粒度更细的 A 股短期收益率预测器，为后续量化/交易信号做准备。

1. 主模型：LightGBM（梯度提升树），不是深度学习，也不跑 GPU。
   - 每个模型 300 棵树、60 个特征。
   - 输入：60 个来自 `tickAlphaBase220` 的 L2/L3 级 tick 因子
     （订单流、盘口、微小价差等预提取特征）。
   - 输出：一只股票下一分钟的官方收益率 `official_ret1`（单位 bp）。
   - 每行样本 = 1 只股票 × 1 天里的 1 分钟（分钟级截面）。
2. 实验矩阵：不是训一个模型，而是训一大堆变体后选优。
   - 66 套设计（42 套路由 + 24 套融合/门控）；
   - 891 条主轨迹 + 720 条嵌套支持轨迹；
   - 每 1 套都有 3 种基座起法：Scratch（从零）、B100、B200（固定前 100/200 棵树再续训）。
3. 分组专家：按"历史属性"把股票切分，每组单独训一套树模型。
   - 价格组（昨收价中位数折分位，5 档组）
   - 波动组（前 3 日官方 ret1 的 RMS 折分位，3 档组）
   - CAP 组（对数流通市值折分位，3 档组）
   - 两两交叉（PriceVol / PriceCAP / VolCAP）
4. 门控收尾：训练一个"门控模型"，根据当天行情决定听哪个专家的话
   （四种：等平均 / 常数加权 / 软概率 / 硬开关）。
5. 时间与数据量：
   - 训练区间 2026-02-02 → 2026-06-30，116 个交易日；
   - 5 折月份交叉验证（held_months 每次留 2 个月）+ 内部早停 + 1 天 embargo；
   - 单模型一次训练矩阵 ≈ 2200 万行 × 60 列（约 5 GB）。
6. 评估（不是回测）：
   - OOF（out-of-fold）预测上按 0/1/3/5/10 bp 交易成本汇总信号收益；
   - 代码里明确说"不是账户收益，也不是策略夏普"；
   - 是信号层面研究，最终交给上线/导师决定实盘。
7. 整轮 ALL 模式预计 ~110 小时，15 线程 CPU，机器没有 GPU。

二、我们改成 Transformer 的方案
--------------------------------

要走的方向：用 GPU 训练 Transformer 模型重建"短期tick级预测"。

1. 任务定义沿用 gaotj 已验证的口径：
   - 输入序列：每只股票的分钟级 220 因子（或 60 因子子集）时间窗；
   - 输出：未来 60 秒 official_ret1，或分档涨跌方向。
2. 架构基线（先做相位 1）：
   - 每只股票一行时序
   - 220 个因子按"同一分钟内特征" fork 每个 ML token，
     逐分钟的 patch 作为序列 unit
   - Embedding + 位置编码 + 双向 Transformer encoder（B8/H8/D512 规模即可起步）
   - 输出 MLP 接在 [CLS]/终点 token 上
3. 训练目标（两种并行试）：
   - 回归：MSELoss 逼近未来 ret1（单位 bp，按当天 std 归一化）
   - 分类：涨/平/跌 3 类均衡 cross-entropy（分类更稳，先跑通）
4. 数据切分：沿用他的 5 折月份固定 CV，避免月泄漏；每折留最后部分做早停。
5. 训练规模（一台 4090 够起步）：
   - 窗口长度：90 分钟（60 因子→一天一个 batch 段）
   - Batch size 先 64~128，之后往上试
   - 一个 epoch 大约 # 想清楚的确切批次后补
6. 评估口径仍沿用 gaotj 的 OOF + 0/1/3/5/10 bp 成本，
   对比同一套 LightGBM 基线，优于基线才算成功。

三、做这件事的"为什么"
-----------------------

1. Transformer 能学到"过去 N 分钟的因子变化趋势 + 相对顺序"这一维度，
   这正是 GBDT 一次性给一行快照所缺失的部分；
2. GPU 加速下单轮实验单元从一天级别缩到小时级，能更快迭代；
3. 与 LightGBM 基线强对照后能明确看到"时序建模是否带来增量信息"。

四、风险
---------

1. 分钟级预测里噪声占主，Transformer 很容易过拟合；
   必须沿用 GBDT 的评审口径，不能只看 Val Loss。
2. 开发周期里"低优先级 ML 任务插队"要先排好。
3. 本文档只是计划记录，具体超参和批次规模等真实训练前还要再定。

后续决定下一步具体实验和训练时再回补该文件。
